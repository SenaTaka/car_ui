# car_ui(OBD2 Scanner + Engine Sound)— 「検索露出はあるのに刺さらない」原因分析

調査日: 2026-08-09 / 対象期間: ASC App Analytics 直近28日

## 1. 現状データの読み方

| 指標 | 値 | 判定 |
|---|---|---|
| Impressions | 2,732(98%が検索) | 母数として小さい(絶対数の限界あり) |
| Imp→PV | 5.0%(136件) | **弱い**(業界平均 3.6%〈AppTweak 2020〉はわずかに上回るが、同ポートフォリオ Engine Sim の 12.2% の半分以下) |
| Tap率 | 2.6%(71件) | 検索結果一覧での選択率が低い |
| PV→DL | 16.2%(22件) | **健全**(プロダクトページに来た人はちゃんと落とす) |

**重要な切り分け**: PV→DL が健全 = スクリーンショットや説明文(=プロダクトページの中身)は機能している。弱いのは Imp→PV、つまり**検索結果一覧の行(アイコン+アプリ名+サブタイトル+★評価)**の段階。スクショ1枚目のコピーはこの段階の CVR には効かない(タップ後にしか見えない)。

**検索意図の核**: 「OBD2」「ELM327」で検索するユーザーの主目的は**故障コード(DTC)読取 = チェックエンジンランプの原因を知りたい**。上位3競合は全てこれを一番手の訴求にしている。加えて Car Scanner は 4.8★/32,000件という圧倒的な社会的証明(★バッジ)を検索結果行に表示できる。

## 3. car_ui の現状表示 vs 実態のギャップ

- 名前/サブタイトル: 「OBD2スキャナー エンジン音付き」/「ELM327メーター・買い切り・サブスクなし」— **DTC(故障コード)への言及が一切ない**。keywords.txt(ja/en-US 双方)にも「DTC」「故障診断」「code」「check engine」系語が皆無。
- アイコン: 汎用の OBD コネクタ+「OBD」の白抜き文字(診断ツール然としたビジュアル、青系)。
- 実態: DTC消去機能は Pro 特典として実装済み(STRATEGY.md 決定ログ 2026-07-13(2))だが、**「実車未検証」を理由にプロモーション(スクショ・説明文)から意図的に除外**(store/ASO_NOTES.md 2026-07-16 の記録)。つまり故障診断を訴求の核にはできない状態。
- レビュー数: STRATEGY.md の記録では公開以来の累計 DL が十数件規模の新規アプリ。★評価バッジがほぼ立たない(または非常に薄い)状態で、4.8★/32,000件の Car Scanner と同じ検索結果一覧に並ぶ。

## 4. 原因の切り分け(検証可能な形で)

仮説A「検索意図とストア表示のズレ」: 支持する根拠は名前/サブタイトル/keywords に DTC 系語が皆無なこと。ただし DTC を前面に出す修正は「実車未検証」の制約と矛盾し、審査済み実装の信頼性リスク(2.3.7 で一度リジェクトされた前例あり=表現の正確性に厳しいカテゴリ)を伴う。**採用不可(安全に実行できない)**。

仮説B「同じ検索意図の中で低競争ワードへ寄せる」: name/subtitle の OBD2/ELM327 は維持しつつ(現在の impression 母数の源)、keywords とサブタイトルの重み付けを「ゲージ/ダッシュボード/エンジン音」という**競合不在の領域**へ再配分。Engine Sim の Imp→PV 12.2% は「検索意図と提供価値が一致している時にどこまで伸びるか」の社内実例として使える。

仮説C「投資しない」: 絶対数(月22DL)が小さいのは事実だが、ASO 修正はメタデータ編集のみで工数 0.5日、コード変更ゼロ・審査リスクもほぼゼロ。エンジン音のみ他社ゼロ地帯という差別化実証済みの資産があるのに使い切っていない状態は「机上の損失」であり、投資しない理由にはならない。

## 5. 推奨する打ち手(1つに絞る)

**採用: 仮説B — 「OBD2診断ツール」競争から降りて「ライブ計器+エンジン音」の無競合ニッチへキーワード再配分**

- 期待効果: 定量予測は困難(絶対数が小さいため)だが、方向性として Imp→PV を現状 5.0% から Engine Sim 実績(12.2%)側へ引き上げる。Imp 数自体は落ちる可能性があるが、母数の質が上がり PV→DL(現状16.2%、健全)を維持したまま総DL増を狙う設計。
- 工数: 0.5日(store/metadata の keywords.txt・subtitle.txt 編集 + ASC API 反映のみ、コード変更なし)。
- 根拠: (1) PV→DL が健全 = プロダクトページ自体は機能している、直すべきは検索結果行。(2) DTC 訴求は実装未検証+審査リスクで採用不可。(3) エンジン音は競合ゼロと確認済み(store/competitive.md)。(4) Engine Sim という自社ポートフォリオ内の対照実験データが「意図一致時の CVR」を裏付けている。

### 具体案(次アクション、コードは書かない)
- EN subtitle: "ELM327 live gauges, no sub" → "Live gauges + real engine sound, no sub"(エンジン音を検索結果行にも出す)
- JA subtitle: "ELM327メーター・買い切り・サブスクなし" → "ライブメーター+エンジン音・買い切り"
- keywords 追加候補(EN): instrument cluster, digital gauge, car dashboard app
- keywords 追加候補(JA): 自分だけのメーター, デジタルメーター, カスタムダッシュボード
- DTC/故障診断系語は今回も追加しない(実車未検証のため)。

## 6. STRATEGY.md への反映案

決定ログへの追記(該当箇所: car_ui の項、日付は本調査日):

```
- 2026-08-09: car_ui の Imp→PV 低迷(5.0%、Engine Sim 12.2%の半分以下)を strategist が調査。
  原因: 検索者の主意図(DTC故障診断)と car_ui の訴求(ライブ計器+エンジン音)がズレている。
  競合(Car Scanner ELM OBD2 4.8★/32,000件、OBD Auto Doctor 4.38★)は軒並み DTC 読取が一番手。
  car_ui は DTC消去を Pro 実装済みだが「実車未検証」のため訴求からは意図的に除外中(継続)。
  → DTC訴求への寄せは審査リスク+信頼性リスクで不採用。代わりに無競合ニッチ(ライブ計器+エンジン音)
  へキーワード/サブタイトルを再配分(工数0.5日・コード変更なし)。PV→DL(16.2%)は健全なため
  プロダクトページ側は変更しない。
```

PV→DL が健全という事実は、次にリソースを割くべきは「スクショ・説明文」ではなく「検索結果行(名前/サブタイトル/keywords)」であることを示す一般則としても記録価値あり(他アプリのファネル診断でも Imp→PV と PV→DL を分けて見る観点として `biz/STRATEGY.md` の分析メモに残す価値あり)。
